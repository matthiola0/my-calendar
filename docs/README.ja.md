## Daybookを使う理由

一般的なToDoリストは「今日は何をする？」から始まります。Daybookはその一段上の「何を変えたいのか、今できる最小で有効な行動は何か」から始めます。

期限のある長期サイクルと成果を決め、フェーズに分け、デイリータスクを大きな方向へ結びます。内蔵AIは必要な日付だけを読み、既存の予定を残したまま、確認可能な提案を作ります。承認するまで何も書き込まれません。

## 特徴

| 意図から | 毎日の行動へ | 学びへ |
| --- | --- | --- |
| 長期サイクル、成果、フェーズ、日付、完了報酬 | AIタスク、繰り返し、時間帯、2分のスタート | 進捗、連続記録、活動メモ、振り返り、カスタム記録 |

- **確認してから使うAI計画**：英語・繁体字中国語・日本語で会話し、長期サイクルとタスクをプレビューしてから適用できます。
- **長期とデイリーの連携**：小さなタスクを目標やフェーズに紐づけると、長期サイクルの進捗が自動更新されます。
- **自分で組み立てる一日**：一日を集中ブロックに分け、PCではドラッグ、スマホでは編集画面から配置できます。
- **実用的な繰り返し**：日・週・月ごとに繰り返し、回数または終了日を設定。今回だけ、またはシリーズ全体を編集できます。
- **習慣を始めやすくする設計**：なりたい自分、行動のきっかけ、調子が悪い日でもできる2分版を記録します。
- **チェック以外の記録**：今日したこと、振り返り、LeetCodeメモなどのカスタム項目を毎日残せます。
- **アカウント分離と端末同期**：Googleまたはユーザー名・パスワードでログインし、各アカウントの内容を独立して同期します。
- **Agent対応**：認証済みのローカルCLIから、coding agentがデータベースへ直接触れずに同じカレンダーを操作できます。

## 『Atomic Habits』からの着想

Daybookは、James Clearの習慣フレームワークの考え方を操作できる項目にしています。

- 結果だけでなく、習慣の先にあるアイデンティティを決める；
- 行動を始めるきっかけを明確にする；
- 2分の最初の行動で始める抵抗を下げる；
- 進捗を見えるようにし、一度休んだ後は早く戻る。

公式の[Atomic Habits要約](https://jamesclear.com/atomic-habits-summary)と[書籍紹介](https://jamesclear.com/atomic-habits)も参照できます。Daybookは独立したオープンソースプロジェクトで、James Clearとの提携関係はありません。

## AIプランナー

長期サイクルの作成、進行中フェーズのデイリータスク化、過負荷の確認、習慣設計、実際の進捗に合わせた今後2週間の調整を依頼できます。

1. 依頼に必要な日付範囲だけを選びます。
2. その範囲の既存タスク、サイクル、フェーズ、時間帯をサーバーで読みます。
3. モデルはデータベースへ直接書かず、構造化された提案を返します。
4. Daybookが日付、件数、リンク、重複を検証します。
5. 内容を確認し、適用するかを選びます。

適用は追加だけを行い、既存項目を削除・上書きしません。設定、制限、データフロー、例は[AIプランナーガイド](ai-planner.md)をご覧ください。

## クイックスタート

Node.js 22.13以上が必要です。

```bash
git clone https://github.com/matthiola0/my-calendar.git
cd my-calendar
npm install
cp .env.example .env.local
npm run dev
```

ユーザー名・パスワード認証には、32文字以上のランダムな`PASSWORD_PEPPER`が必要です。Google OAuthとWeb AIプランナーは任意で、AIプランナーにはサーバー側の`GROQ_API_KEY`が必要です。`.env`ファイルはコミットしないでください。

```bash
npm run lint
npm run build
npm run db:generate # db/schema.tsを変更した場合のみ
```

## プロジェクト構成

```text
app/components  UIとクライアント操作
app/lib         認証、i18n、カレンダー、LLM計画ロジック
app/api         認証済みサーバールート
db              D1スキーマとマイグレーション
docs            プロジェクトドキュメント
scripts         ローカルカレンダーagent CLI
```

agentコマンドの詳細は[AGENTS.md](../AGENTS.md)にあります。カレンダー内容は個人データです。公開ログ、issue、スクリーンショット、commitには含めないでください。
